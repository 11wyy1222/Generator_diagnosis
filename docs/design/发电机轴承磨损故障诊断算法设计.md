# 发电机轴承磨损故障诊断算法设计

## 1. 文档目的

本文档定义发电机轴承磨损故障诊断算法。算法面向双馈和半直驱两类机型，以单个传感器的一条原始振动波形为一个输入样本并独立输出诊断结果。当前没有逐条专家确认标签，因此第一阶段采用时间范围标签下放形成的单波形弱监督标签：正常范围内通过准入检查的波形标为正常，异常范围内通过准入检查的波形标为异常。

第一阶段目标是区分正常与故障；后续在不修改主干输入、标签格式和模型总体结构的前提下，扩展到外环、内环、滚动体和保持架故障定位，并保留对其他局部故障的识别能力。

## 2. 已确认的业务边界

### 2.1 机型与测点

- 双馈机型具有驱动端和非驱动端测点，分别对应不同轴承。
- 双馈波形的 `sensor_position` 取 `drive_end` 或 `non_drive_end`，直接表示当前测点位置。
- 半直驱机型设置 4 个振动测点，所有测点共同观测同一组 2 个同型号发电机轴承。
- 半直驱波形的 `sensor_position` 固定取 `12点`、`3点`、`6点`、`9点`。
- 同一条半直驱样本直接传入一组适用于该双轴承范围的四部件特征阶次，不维护“测点对应某一个轴承”的映射。
- 半直驱 4 个测点分别产生独立结果，不进行模型内测点融合。单测点结果表示其所观测的双轴承范围，不直接区分两个物理轴承中的哪一个发生故障。
- `sensor_position` 表示传感器安装测点。当前测量方向信息不确定，因此不使用测点间幅值比、相位、互谱或相干性特征。

### 2.2 故障范围

轴承磨损泛指轴承局部故障，包括但不限于：

- 外环故障；
- 内环故障；
- 滚动体故障；
- 保持架故障。

BPFO、BPFI、BSF、FTF 四类理论频率用于定位已知部件故障，但不能覆盖全部轴承磨损形式。因此算法必须支持“已判故障但无法定位到四个已知部件”的结果。

### 2.3 数据与推理约束

- 每条波形独立训练和推理，每个传感器各输出一个结果。
- 当前第一阶段标签来自测点时间范围，不等同于逐条波形的专家确认结论；正常范围统一取正常数据上线时间起一个自然月，异常弱标签只取故障结束时间向前一个自然月的核心异常范围。核心异常范围内的单波形标签仍存在噪声，模型学习目标首先是区分“来自正常范围”与“来自核心异常范围”的波形。
- 当前每条波形只记录一个平均转速，无法获知采样期间的瞬时转速及其变化。
- 平均转速从文件名提取，仅用于工况筛选、作为模型辅助特征，以及将故障特征阶次换算为近似理论频率。
- 第一版只使用固定 Hz 网格的普通频谱和包络频谱，不使用阶次谱，也不执行 Hz 到阶次轴的转换。
- 后续即使平台提供同步连续转速序列，也不将阶次谱纳入本方案；如需研究，另行形成独立方案，不影响本文档定义的模型输入。
- 当前优先支持单一故障训练，但标签和输出结构兼容复合故障。

当前数据分配如下，两个机型分别训练和评估：

| 机型 | 开发项目（训练与验证） | 外部测试 | 解释限制 |
|---|---|---|---|
| 半直驱 | 1 个项目、1 台机组、4 个测点；4 个正常范围和 4 个核心异常范围 | 同项目另一台机组的 1 个测点，具有 1 个正常范围和 1 个核心异常范围 | 4 个测点范围属于同一机组的相关观测，不是 4 个独立故障事件；外部测试属于跨机组 |
| 双馈 | 1 个项目、1 台机组、1 个测点；1 个正常范围和 1 个异常范围 | 另一个项目目前只有 1 个测点的 1 个异常范围 | 开发侧只有 1 个异常事件，事件多样性很低 |

开发项目的核心异常范围先按实际经过时间等分为前、中、后三个相对位置，再在每段内形成不重叠时间块，并以时间块为单位按约 70%/30% 分层随机划分训练集与验证集；正常范围不分前、中、后，只在完整范围内按时间块约 70%/30% 随机划分。半直驱外部测试包含正常范围和核心异常范围；双馈外部测试只包含核心异常范围。所有测试均在模型、预处理和评估方法冻结后使用。

## 3. 总体算法架构

```text
单测点原始波形
├─ 原始波形 → 时域编码器 → z_raw ───────────────────────┐
└─ 普通 Hz 频谱与包络 Hz 频谱按通道堆叠              │
   → 双通道频谱编码器 → z_spectrum ────────────────────┤
归一化平均 RPM 标量 ───────────────────────────────────┤
                                                        ↓
                       谱形融合层 → 完整谱形特征 z_spec

四部件连续机理特征
├─ 总体聚合 → 总体机理 MLP → z_phy_global
└─ 共享部件机理 MLP → z_phy[c]

z_spec + 可靠度门控后的 z_phy_global
→ 总体异常融合头 → abnormal_probability

z_spec + 可靠度门控后的各部件 z_phy[c]
→ 四个候选部件独立分类头 → component_probabilities
```

算法包含三个相互补充的能力：

1. 完整谱形只保留两条编码路径：原始波形时域分支，以及普通频谱/包络频谱双通道分支。归一化平均 RPM 作为一个标量在融合阶段拼接，不设置独立 RPM 编码器。
2. 每条波形统一提取外环、内环、滚动体和保持架四组底层连续机理特征。每组特征分别编码为 z_phy[c]，供对应部件分类头使用；四个 z_phy[c] 再聚合形成 z_phy_global，供总体异常头使用。底层频谱特征不重复提取。
3. 总体异常融合头独立于四个部件概率，不能用四部件概率的最大值或并集替代。这样既利用现有机理算法较强的正常/故障分辨能力，也保留谱形分支对跑圈、打滑等四部件机理未覆盖故障的识别能力。总体概率与四部件概率分别输出，后续解释和业务决策不属于模型职责。

## 4. 样本定义与标签

### 4.1 合并后的样本清单

每条记录同时保存波形元数据和诊断标签，推荐使用 JSONL 格式，每行对应一条波形：

```json
{
  "sample_id": "sample_001",
  "fault_event_id": "fault_event_20260301",
  "range_id": "fault_range_20260301_drive_end",
  "sample_group_id": "fault_range_20260301_drive_end_train_block_01",
  "waveform_path": "[waveform_path]",
  "acquisition_time": "2026-03-01 10:20:30",
  "sampling_rate_hz": 25600.0,
  "rpm": 1480.0,
  "rpm_source": "filename",
  "component_orders": {
    "outer_race": 8.0,
    "inner_race": 10.0,
    "rolling_element": 4.0,
    "cage": 0.4
  },
  "machine_type": "dfig",
  "sensor_position": "drive_end",
  "is_observed_scope_abnormal": true,
  "component_labels": {
    "outer_race": null,
    "inner_race": null,
    "rolling_element": null,
    "cage": null
  },
  "label_source": "abnormal_time_range"
}
```

字段定义：

| 字段 | 含义                                                                                                             |
|---|------------------------------------------------------------------------------------------------------------------|
| `sample_id` | 单条波形的唯一标识，也是样本清单主键                                                                             |
| `fault_event_id` | 业务方直接提供的同一次持续故障分组标识，用于故障事件统计，不作为模型输入；同一故障过程下多个测点范围共享该值，确认正常时填 `null` |
| `range_id` | 当前波形所属的机组—测点—时间范围标识，用于追溯范围标签，不作为模型输入 |
| `sample_group_id` | 训练集与验证集切分使用的时间块标识，不作为模型输入。核心异常范围按前、中、后三个相对位置分层后，以完整时间块为单位随机划分；正常范围直接以完整时间块为单位随机划分。不得按单条波形随机打散。 |
| `waveform_path` | 单列原始振动波形的文件路径或统一数据引用；业务方不需要预先提供 FFT 或包络频谱，二者由算法预处理模块生成 |
| `acquisition_time` | 波形采集时间，用于时间排序、时间块切分和泄漏检查 |
| `sampling_rate_hz` | 采样率，单位 Hz                                                                                                  |
| `rpm` | 该波形记录的平均转速；不代表采样期间转速恒定                                                                     |
| `rpm_source` | 转速来源，当前为 `filename`，后续可为 `platform`                                                                 |
| `component_orders` | 随当前样本直接传入的外环、内环、滚动体和保持架特征阶次                                                         |
| `machine_type` | `dfig` 或 `semi_direct`                                                                                          |
| `sensor_position` | 当前波形对应的唯一传感器测点位置，详细规则见下文。                                                               |
| `is_observed_scope_abnormal` | 从当前波形所属时间范围下放得到的第一阶段二分类弱标签，只允许 `true/false`。它表示范围归属，不代表该单条波形已经被专家独立确认。 |
| `component_labels` | 当前诊断范围的四部件标签，每项取 `true/false/null`。半直驱不据此区分两个物理轴承                               |
| `label_source` | 标签证据来源                                                                                                     |

`sensor_position` 定义如下：

- 每条波形必须且只能对应一个 `sensor_position`。
- 双馈取 `drive_end` 或 `non_drive_end`，分别表示驱动端测点和非驱动端测点。
- 半直驱的 4 个实际测点取 `12点`、`3点`、`6点`、`9点`。
- 文件名无法唯一解析为上述测点时拒绝样本，不使用 `unknown` 混入正式数据集。
- 该字段只标识波形由哪个传感器测点采集，不表示轴承编号。
- 四部件特征阶次由上游随样本直接传入，不通过其他元数据查询。

总体标签规则：

- 正常时间范围内通过数据准入检查的每条波形统一标记 `is_observed_scope_abnormal=false`。
- 故障结束时间向前一个自然月的核心异常范围内，通过数据准入检查的每条波形统一标记 `is_observed_scope_abnormal=true`；原始完整异常范围中早于核心范围的历史波形不自动生成监督标签。
- 上述标签是范围标签传播得到的弱监督标签。特别是 `true` 只表示波形来自已确认异常范围，不表示该波形上必然能观察到明显故障特征。
- 当前监督训练集不接受 `is_observed_scope_abnormal=null`；不属于已确认正常或异常范围、位于范围边界争议区，或无法可靠关联范围的波形进入单独无监督清单。
- `label_source` 必须记录标签来自正常范围还是异常范围，以便后续获得逐波形专家结论时区分和替换弱标签。

部件标签规则：

- `true`：已经确认该部件故障。
- `false`：已经明确排除该部件故障。
- `null`：部件状态未知，不参与该部件输出的监督损失。

异常范围标签只自动生成总体二分类标签，不自动生成部件正标签。只有明确确认是单一部件故障时，其他部件才能标为 `false`；如果只发现某一部件故障但不能排除复合故障，其他部件必须标为 `null`。确认正常范围可将四个部件标为 `false`，但第一阶段不启用部件定位训练。

### 4.3 标签来源

推荐值包括：

- `normal_time_range`：样本位于已确认正常时间范围，传播为单波形正常弱标签；
- `abnormal_time_range`：样本位于已确认异常时间范围，传播为单波形异常弱标签；
- `inspection`：单条波形或其对应状态有拆检证据；
- `expert_review`：单条波形经专家独立复核；
- `algorithm_rule`：现有 FFT 机理规则；
- `unknown`：来源不明确。

`label_source` 不作为模型输入，用于标签追溯和训练样本筛选。当前范围传播样本作为同一弱监督基线使用，不增加 `confidence` 字段；以后获得逐波形 `inspection` 或 `expert_review` 结论时，应保留原始范围记录并新增或更新逐波形复核记录。

## 5. 四部件特征阶次直接输入

外环、内环、滚动体和保持架的特征阶次由上游随每条样本直接传入：

```json
{
  "component_orders": {
    "outer_race": 8.0,
    "inner_race": 10.0,
    "rolling_element": 4.0,
    "cage": 0.4
  }
}
```

以上数值仅为有效字段格式示例，不代表所有轴承的实际阶次。算法不通过其他元数据或额外配置 ID 查询阶次，也不负责读取 `故障数据/故障对应表.xlsx`。故障对应表到 `component_orders` 的转换由上游完成。

轴承型号名称仅作为可选追溯元数据，允许缺失，不作为样本准入条件、模型输入或机理计算依据。机理计算以样本实际提供的 `component_orders` 为准。

约束规则：

- 四个字段分别表示 BPFO、BPFI、BSF 和 FTF 对应的特征阶次。
- 每个值应为有限正数；缺失或非法值使用缺失状态表达，不能用 `0` 冒充有效阶次。
- 训练和推理使用相同字段语义及单位。
- 单个部件阶次缺失时，只将该部件的机理特征标记为不可用，不影响完整谱形分支以及其他阶次有效部件的机理分析。

`component_orders` 只用于第 7 节定义的理论频率计算，不作为分类模型特征。

## 6. 信号预处理

### 6.1 数据准入与开发阶段筛选

外部输入只需要提供单列原始振动波形及样本清单中的元数据。普通 FFT 频谱和包络频谱均由算法预处理模块根据原始波形生成，业务方不需要额外准备两列频谱数据。

进入模型前应完成以下校验与筛选：

- 空数据或无法执行 FFT 的数据剔除；
- 采样率和平均 RPM 必须能够解析；
- 平均 RPM 必须位于人工配置的业务允许范围 `rpm_range` 内；
- 削顶、饱和等信号失真数据应由前置信号失真算法识别并剔除。

执行位置分为两个阶段：

- **开发阶段**：数据库尚未建好时，由本地样本清单构建器或数据加载器读取每条样本的 `rpm`，按 `rpm_range.min <= rpm <= rpm_range.max` 筛选，并记录剔除原因。
- **生产阶段**：数据库建好后，将同一 `rpm_range` 条件前移到数据库查询；模型入口仍保留参数合法性检查，防止绕过查询的数据进入模型。

开发和生产必须使用同一份 RPM 范围配置，不能根据训练集、验证集或测试集结果分别调整。筛选结果不作为模型特征。

### 6.2 原始波形时域输入

```text
准入后的原始波形
→ 去均值
→ 必要时使用训练阶段固定的全局缩放系数
→ 输入时域编码器
```

时域输入保留冲击发生位置、波形形状、周期性、瞬态和间歇性信息。第一版默认使用完整波形，不在此步骤计算手工时域统计特征。

### 6.3 普通谱/包络谱双通道输入

双通道频谱由同一条准入波形生成。

通道 1 为普通频谱：

```text
去均值后的原始波形
→ 加窗
→ 单边 FFT
→ 截取统一有效频带
→ 插值到固定 Hz 网格
→ 普通线性幅值谱
```

通道 2 为包络频谱：

```text
去均值后的原始波形
→ 直接执行 Hilbert 包络
→ 去除包络直流分量
→ 加窗并执行单边 FFT
→ 截取统一有效频带
→ 插值到与通道 1 相同的固定 Hz 网格
→ 包络线性幅值谱
```

两个通道按通道维堆叠后共同输入一个双通道频谱编码器。普通频谱和包络频谱只是双通道输入的组成部分，不再作为两个独立模型分支。第一版不选择冲击共振频带，不进行带通滤波，也不使用谱峭度选择解调频带。

### 6.4 线性幅值与模型输入

第一版不对普通频谱或包络频谱执行 `log1p` 等对数压缩。频谱编码器和机理特征提取均使用线性幅值谱。

禁止对每条样本单独执行均值方差标准化、最大值归一化或总能量归一化。若模型训练需要缩放，只允许使用训练集确定、并在验证、测试和推理阶段固定的全局线性缩放系数：

\[
A_{scaled}=\frac{A}{S_{train}}
\]

第一版谱形输入只有两条编码路径：

```text
原始波形 → 时域编码器
普通线性幅值频谱和包络线性幅值频谱按同一固定 Hz 网格堆叠
→ 双通道频谱编码器
```

双通道输入定义为：

```text
spectrum_input.shape = [2, frequency_bin_count]
spectrum_input[0] = fft_spectrum
spectrum_input[1] = envelope_spectrum
```

普通频谱和包络频谱不再分别进入独立编码器，也不做首尾拼接。归一化平均 RPM 作为谱形融合阶段的一个标量输入。

#### 6.4.1 四部件连续机理证据

四部件连续机理证据从上述普通频谱和包络频谱提取一次，分别围绕外环、内环、滚动体和保持架的理论频率及 1～5 阶谐波计算。

本节只规定特征来源和单次提取原则。现有字段复用、计算公式、搜索中间量与 `mechanism_features[c]` 的完整定义统一见第 8.1 节；理论频率的使用边界见第 7 节。

#### 6.4.2 总体连续机理证据

总体连续机理证据只由四部件连续证据聚合，不附加外部总体统计字段，也不从频谱重复提取另一套特征。具体输入边界见第 8.1 节，编码与聚合方式见第 9.2 节。

第一版模型最终输入包括：原始波形、双通道频谱、归一化平均 RPM、四部件连续机理证据、总体聚合证据，以及机理特征的有效掩码和可靠度。

### 6.5 固定频率网格与故障频率可分辨性

普通频谱和包络频谱统一使用 Hz 频率轴。固定网格的最高频率和分辨率应根据以下因素确定：

- 四类故障在业务转速范围内换算得到的最高近似理论频率及最高分析谐波；
- 需要分析的边带范围；
- 最短波形对应的 FFT 频率分辨率；
- 采样率及抗混叠后的有效频带；
- 可接受的模型输入长度和推理耗时。

FFT 频率分辨率为：

\[
\Delta f=\frac{f_s}{N}
\]

其中 \(f_s\) 为采样率，\(N\) 为波形采样点数。频率分辨率和有效频带不作为通用质量特征，其用途仅是判断轴承故障频率能否被有效分析：

- 按平均 RPM 换算的故障基频及待分析谐波是否位于有效频带内；
- 目标频率附近是否具有足够的 FFT 频点用于峰值搜索；
- 相邻故障频率、谐波或主要干扰频率是否能够在当前分辨率下区分。

若某个候选部件的理论频率或谐波超出有效频带，或无法在当前分辨率下可靠区分，则只将该候选的机理特征标记为不可用或低可靠度，不否定完整频谱分支的异常判断。

### 6.6 频率轴与模型输入

FFT 输出 Hz 频率轴和对应线性幅值。频率轴用于：

- 将幅值插值到固定 Hz 频率网格；
- 搜索近似理论频率、谐波和边带；
- 计算峰值位置偏差；
- 判断目标频率是否位于有效频带并具备足够分辨率。

完成插值后，所有样本共享同一固定 Hz 网格，每个数组索引对应确定的频率位置。因此网络只输入固定频率网格上的线性幅值，不把频率轴作为重复通道输入。

### 6.7 波形长度与内部窗口

第一版默认使用完整波形生成普通频谱和包络频谱，不强制把一条波形切成多个独立样本。完整波形能够保留更好的频率分辨率，有利于识别低频 FTF、相近谱峰和精细边带。

`N` 读取每条波形第一列长度。同一机组、同一测点只保留目标长度一致的波形，长度不一致文件从建模数据集剔除并登记，但不覆盖原始文件。因此同一测点的有效时域输入不需要裁剪、补零或长度重采样，可以直接按完整波形组成批次。若不同测点之间的波形长度不一致，训练时按测点或相同长度分组组成批次，时域编码器使用自适应分段池化映射为固定维度。频谱分支仍使用完整波形计算普通频谱和包络频谱，并统一插值到固定 Hz 网格。

只有在原始波形过长或故障明显间歇时，才增加内部窗口分析。即使使用窗口，也应将窗口结果聚合为原始 `sample_id` 的一个输出；同一原始波形的所有窗口必须位于同一个数据集，不能跨训练集、验证集和测试集。

### 6.8 平均转速的使用边界

平均 RPM 必须在进入模型前完成可解析性和业务范围筛选。开发阶段由本地数据加载器执行，生产阶段优先由数据库查询执行；模型入口始终保留合法性检查。通过筛选后的平均 RPM 用于：

- 作为模型的工况辅助特征；
- 将样本直接传入的四部件特征阶次换算为近似理论频率，供带容差的峰值搜索使用。

本章不包含阶次处理。若后续业务增加其他信号预处理方式，应由上游信号处理模块形成经过验证的新输入，再单独评估是否接入诊断模型。
## 7. 近似理论故障频率计算

上游直接提供外环、内环、滚动体和保持架对应的故障特征阶次；这些值可由上游业务系统从故障对应表取得，但本算法不读取该表，也不通过其他标识查询。本文档只规定统一计算语义。

设：

- \(RPM\)：当前波形平均转速；
- \(f_r=RPM/60\)：轴转频，单位 Hz；
- \(O_c\)：故障对应表中部件 \(c\) 的特征阶次；
- \(f_c\)：按平均转速估计的部件 \(c\) 近似理论故障频率，单位 Hz。

近似理论故障频率计算为：

\[
f_c=f_r\times O_c=\frac{RPM}{60}\times O_c
\]

四个部件分别使用对应表中的阶次值：

```text
BPFO_hz = RPM / 60 × outer_race_order
BPFI_hz = RPM / 60 × inner_race_order
BSF_hz  = RPM / 60 × rolling_element_order
FTF_hz  = RPM / 60 × cage_order
```

第 \(n\) 阶谐波的理论位置为：

\[
f_{c,n}=n\times f_c=\frac{RPM}{60}\times nO_c
\]

`f_c` 和 `f_{c,n}` 是确定性的频谱搜索锚点及内部计算中间量，不是故障强度或故障存在性的证据，也不直接输入总体机理 MLP 或部件机理 MLP。模型使用的是围绕这些锚点测得的连续观测证据，例如峰值幅值、相对频率偏差、峰值/局部背景比、谐波与边带结构。理论频率及实际峰值绝对 Hz 位置仅用于计算、频带覆盖判断和内部解释日志。

由于没有同步连续转速，以上计算只能得到基于平均 RPM 的近似理论频率，不能证明故障峰在整段采样期间始终位于该频点。峰值搜索窗必须覆盖 FFT 分辨率、平均转速误差、未知的采样期内转速波动以及轴承滑移；当这些不确定性无法合理限定时，应降低机理证据可靠度，不能把理论频点附近未发现峰值视为强负证据。

采样率和平均 RPM 在进入计算模块前必须通过合法性及 `rpm_range` 校验。理论频率计算模块还验证：

- 当前样本直接传入的对应部件特征阶次存在、为有限正数；
- 理论频率及其分析谐波不超过当前频谱的有效频率范围。

## 8. 机理特征设计

四部件机理特征只从普通频谱和包络频谱提取一次，同时供总体异常头和四部件头使用：

```text
mechanism_features.shape = [4, feature_count]
mechanism_valid_mask.shape = [4, feature_count]
```

### 8.1 机理分支输入

每个部件 `c` 的处理量分为第 7 节定义的搜索参数与中间量，以及本节定义的模型连续机理特征；只有后者与有效掩码共同输入机理 MLP。

现有代码可直接提供：

1. `m_ArrMaxPoint[(c,n)]["value"]`：普通频谱 1～5 阶理论频率搜索窗内的峰值幅值；
2. `m_ArrMaxPoint[(c,n)]["number"]`：上述峰值所在的 FFT 频点，仅作为中间量；
3. `m_ArrMaxPoint_en[(c,n)]["value"]`：包络频谱 1～5 阶理论频率搜索窗内的峰值幅值；
4. `m_ArrMaxPoint_en[(c,n)]["number"]`：上述峰值所在的 FFT 频点，仅作为中间量；
5. `mid`、`mid_en`：普通频谱和包络频谱的全谱中位数，仅作为背景辅助值；
6. 单波形部件峰值相对全谱背景值：

\[
FFTValue_c=\frac{\sum_{n=1}^{5}A^{fft}_{c,n}}{mid+\epsilon}
\]

\[
EnvelopeValue_c=\frac{\sum_{n=1}^{5}A^{env}_{c,n}}{mid_{en}+\epsilon}
\]

需要在特征提取模块新增计算，其中实际峰值绝对 Hz 位置是中间量，其余连续观测证据按定义组成模型特征：

1. 各阶峰值对应的实际频率 Hz，用于计算和日志，不直接输入机理 MLP；
2. 各阶实际峰值与理论频率的相对偏差；
3. 各阶理论频率搜索窗附近的局部背景中位数；
4. 各阶峰值/局部背景比；
5. 1～5 阶有效谐波数量、峰值总和及衰减关系；
6. 左右边带幅值、边带/主峰比、边带间隔和对称性；
7. 普通谱和包络谱在同一部件上的证据组合。

最终 `mechanism_features[c]` 只包含峰值幅值及其聚合量、相对频率偏差、局部背景、峰值/背景比、谐波数量与衰减、边带结构和谱间一致性。搜索参数与中间量不作为分类输入。

总体机理向量仅使用上述当前波形机理特征。`pouout_value` 等多波形汇总结果，以及 `m_bFault`、`final_fault_level`、`winmax[-1]` 和报警字符串等离散规则结果均不作为模型输入，只保留为独立规则基线。

### 8.2 有效掩码与可靠度

`valid_mask` 区分“有值”和“无法计算”：

- 部件阶次和平均 RPM 均为有限正数，且目标理论频率位于有效频带内时，对应峰值特征的 `valid_mask=1`；
- 部件阶次或 RPM 缺失、非法，或目标理论频率超出有效频带时，`valid_mask=0`；
- 某一阶谐波不可用只屏蔽该阶特征，不影响同一部件的其他有效谐波；
- `valid_mask=0` 时，特征占位值统一填 0，不能把该 0 解释为“没有故障峰”。

可靠度用于限制有效机理特征对分类头的影响，按第 9.3 节的输入有效性、频带覆盖和测量条件计算。可靠度不表示故障强度；峰值幅值、背景比、谐波和边带等连续量才表示故障支持程度。

机理特征从未进行逐样本标准化的线性幅值谱提取，输入 MLP 前使用训练集统计量统一缩放。

## 9. 模型设计

### 9.1 完整谱形编码器

完整谱形只使用两条编码路径：

```text
原始波形 → 轻量多尺度时域 1D CNN → 自适应分段池化 → z_raw
stack(普通谱, 包络谱) → 浅层双通道频谱 1D CNN → 分段池化 → z_spectrum
```

时域路径使用少量不同卷积核尺度并行或串联提取特征：较大卷积核用于捕获周期结构和较宽冲击，较小卷积核用于捕获尖峰和局部波形纹理。初期不引入 LSTM、Transformer 或较深残差网络。自适应分段池化既保留波形不同区段的信息，也支持不同测点波形长度不一致时输出固定维度。

双通道频谱输入为 `[2, frequency_bin_count]`，两个通道共享同一固定 Hz 网格，使编码器能够学习普通谱和包络谱在相同频率位置的联合响应。普通谱和包络谱不再分别设置独立编码器。初期使用浅层 1D CNN；只有当独立验证表明浅层网络存在稳定欠拟合且残差结构有明确增益时，才升级为轻量 ResNet1D。

频谱编码器需要保留谱峰所处的具体 Hz 区间，可使用分段池化、固定频率位置编码，以及注意力池化或展平投影，不能只对整个频率维执行一次全局平均池化。

第一版默认使用确定性的分段池化或展平投影，不默认启用注意力池化。注意力机制只有在相同数据切分上的专项对比中获得稳定收益后才进入生产模型。

平均 RPM 作为融合阶段的标量输入：

\[
RPM_{norm}=\frac{RPM-RPM_{min}}{RPM_{max}-RPM_{min}}
\]

`RPM_min` 和 `RPM_max` 由训练集或业务允许范围固定。最终得到：

```text
z_spec = SpectrumFusion([z_raw, z_spectrum, rpm_normalized])
```

#### 9.1.1 开源结构借鉴边界

初期网络只借鉴公开项目中已经验证过的通用结构思想，并依据本项目输入和标签语义独立实现：

- 借鉴 `Xiaohan-Chen/bear_fault_diagnosis` 的多尺度时域卷积思想，但不沿用其固定长度输入、LSTM 解码器、Softmax 十分类及随机窗口切分流程；
- 借鉴 `Xiaohan-Chen/transfer-learning-fault-diagnosis-pytorch` 的 1D CNN/ResNet 可替换主干设计，但第一版默认使用浅层 1D CNN；
- `DG-for-RMFD` 中的域泛化方法仅在多个机型、测点或工况域具有足够独立事件后作为专项实验，不进入第一版；
- `BearingPGA-Net` 的知识蒸馏和量化仅在完整模型验证有效且现场部署资源受限时使用。

开源项目在 CWRU 等实验数据集上的指标不能直接作为本项目效果依据，最终结构必须通过按独立 `sample_group_id` 切分的验证和测试确定。`fault_event_id` 用于事件级汇总，不作为本次训练/验证切分键；同一故障事件在同一自然日或同一连续采集批次的多测点波形必须共享同一 `sample_group_id` 和切分结果。

### 9.2 机理特征编码器

四部件共用同一个 MLP，输入为第 8 节定义的特征值和有效掩码：

```text
z_phy[c] = SharedMechanismMLP([
    mechanism_features[c] * mechanism_valid_mask[c],
    mechanism_valid_mask[c]
])
```

总体机理向量不重复提取另一套频谱特征，只聚合四个部件编码结果：

```text
z_phy_global = GlobalMechanismMLP([
    aggregate(z_phy[outer_race], z_phy[inner_race],
              z_phy[rolling_element], z_phy[cage])
])
```

### 9.3 谱形与机理融合

机理特征首先由 `valid_mask` 屏蔽无法计算的字段，再使用可靠度约束门控与谱形融合。

总体机理可靠度 `q_global` 仅根据四部件有效特征覆盖情况确定。总体融合为：

```text
v_global = ProjectGlobal(z_phy_global)
g_global = q_global * sigmoid(GlobalGate([z_spec, v_global, q_global]))
gated_v_global = g_global * v_global
h_abnormal = LayerNorm(z_spec + gated_v_global)
abnormal_logit = AbnormalHead([h_abnormal, z_spec * gated_v_global])
```

候选部件 `c` 的可靠度为：

\[
q_c=q_{input,c}\times q_{range,c}\times q_{measurement,c}
\]

其中：

- `q_input`：对应部件阶次和平均 RPM 是否有效；
- `q_range`：理论基频及 1～5 阶谐波在有效频带内的覆盖比例；
- `q_measurement`：当前频率分辨率、局部底噪、峰值重叠和搜索窗条件是否满足测量要求。

候选部件融合为：

```text
v_c = Project(z_phy[c])
g_c = q_c * sigmoid(GateMLP([z_spec, v_c, q_c]))
gated_v_c = g_c * v_c
h_c = LayerNorm(z_spec + gated_v_c)
component_logit[c] = ComponentHead[c]([
    h_c,
    z_spec * gated_v_c
])
```

上述 `ComponentHead[c]` 实际实现为四个参数相互独立的轻量分类头：`OuterRaceHead`、`InnerRaceHead`、`RollingElementHead` 和 `CageHead`。四个头可以共享前面的谱形编码器、机理编码器和门控计算，但不共享最终分类层参数。

所有机理路径都必须经过对应门控；谱形路径始终直接进入总体异常头和四部件头。机理证据无效或可靠度为 0 时，模型仍可依赖 `z_spec` 输出结果。

理论频点附近未发现明显峰值时，只有在输入、频带和测量条件均满足时才可作为有限负证据；否则应视为未知。跑圈、打滑等四部件理论频率未覆盖的故障仍主要由谱形路径识别。

### 9.4 机理辅助头与门控使用监控

为防止端到端训练时主模型仅依赖 `z_spec`、长期忽略机理分支，第一阶段增加总体机理辅助头；该头用于训练监督，并在生产推理中保留为内部监控信号：

```text
mechanism_aux_logit = MechanismAuxHead(z_phy_global)
p_phy_aux = sigmoid(mechanism_aux_logit)
```

总体机理辅助头使用 z_phy_global 独立预测当前样本是否故障，并通过验证集上的整体指标判断机理分支是否具有故障辨别能力，不与总体异常头共享最终输出。其约束如下：

- 只在 `is_observed_scope_abnormal` 已知且 `q_global > 0` 时计算辅助损失，并使用 `q_global` 降低低可靠度机理证据的监督权重；
- 第一阶段不增加四部件辅助头；只有相应部件具有足够可靠标签时才另行评估；
- `mechanism_aux_logit` 和辅助概率分数不进入对外单波形输出，不用于替代 `abnormal_probability`；
- 生产模型默认保留该轻量辅助头用于内部监控，但不对外输出；若后续因明确的资源约束将其裁除，必须记录辅助头已禁用，其他门控监控字段仍须保留，训练和独立评估结果不得删除。

训练、验证和推理日志需要监控门控是否真正使用机理分支，至少记录：


- 总体 `q_global`、学习门值 `g_global`，并仅在 `q_global > 0` 时记录 `g_global/q_global`；g_global：决定最终模型使用多少机理信息
- 第一阶段记录各部件 `q_c` 和特征覆盖情况，但不计算部件门值 `g_c`；第二阶段启用部件诊断头后，才记录各部件 `g_c`，并仅在对应 `q_c > 0` 时记录 `g_c/q_c`；
- 门控后机理向量与谱形向量的范数比；
- 机理辅助概率与最终异常概率；
- 可选的门控融合前后异常 logit 差值，用于判断机理分支对本次结果的实际影响；
- 当前样本是否因机理特征无效而退化为仅谱形判断。

汇总评估应按机型、测点、转速区间和正常/故障标签统计门值均值、分位数、近零比例及高可靠度但低门值比例。门值长期接近 0 表示机理分支可能被忽略；门值长期饱和接近可靠度上限则可能表示模型过度依赖机理分支。两种情况都必须结合四组对比实验和独立测试集判断，不能仅凭门值大小认定模型有效或无效。

### 9.5 输出头

模型输出：

```text
p_abnormal
p_outer_race
p_inner_race
p_rolling_element
p_cage
```

四个部件使用独立 Sigmoid，不使用 Softmax。当前单一故障数据可以训练该结构，后续增加复合故障时无需修改输出层。

四个部件分类头的最终分类层参数相互独立；独立 Sigmoid 允许任意多个部件同时具有较高故障概率。共享的谱形和机理编码器不改变四个输出头的独立性。

不单独训练“其他故障”类别。推理时通过整体异常概率与四个已知部件概率的关系得到“未定位局部故障”。

## 10. 损失函数与缺失标签

```text
L = λa × BCE/Focal(p_abnormal, y_abnormal)
  + λc × Σ component_mask[c] × ClassBalancedBCE(p_component[c], y_component[c])
  + λp × q_global × BCE(p_phy_aux, y_abnormal)
  + λr × regularization
```

规则如下：

- 当前监督训练样本的 `is_observed_scope_abnormal` 必须为 `true/false`，因此不使用 `abnormal_mask`。
- 第一阶段的 `y_abnormal` 来自 `normal_time_range` 或 `abnormal_time_range` 的范围标签传播，属于单波形弱监督目标；损失优化的是范围来源可分性，不应解释为已获得逐波形真值监督。
- 某个 `component_labels` 为 `null` 时，不计算该部件损失。
- 只知道轴承故障但不知道部件时，训练总体异常主头；当 `q_global > 0` 时同时训练总体机理辅助头，不计算四部件损失。
- 已确认轴承正常时，可以将四个部件均作为负标签。
- 只有明确确认单一部件故障时，其他三个部件才作为负标签。
- 当前范围传播标签在第一版基线中等权使用，`label_source` 只用于追溯和分组评估，不再另设 `confidence`。如果以后混入逐波形拆检或专家复核标签，再单独设计证据来源采样或权重实验。
- `p_phy_aux` 只由总体机理向量产生；`q_global=0` 时不计算机理辅助损失。
- `λp` 保持为较小权重并由独立验证集确定，避免机理辅助任务压制最终异常任务。
- 机理辅助损失只用于保证机理编码器具有可检验的预测信息，不将辅助概率作为最终诊断概率。

异常检测头不能由四个部件概率简单替代，否则模型无法覆盖跑圈、打滑等四类之外的局部故障。
## 11. 单波形输出结构

```json
{
  "sample_id": "sample_001",
  "abnormal_probability": 0.92,
  "component_probabilities": {
    "outer_race": 0.81,
    "inner_race": 0.08,
    "rolling_element": 0.12,
    "cage": 0.05
  }
}
```

以上概率仅用于说明字段格式，不是实际推理结果。模型只输出概率，不生成正常、复核、故障或部件诊断结论。

### 11.1 字段说明

| 字段 | 类型 | 含义 |
|---|---|---|
| `sample_id` | `string` | 当前波形的唯一标识，用于关联样本清单中的机型、测点位置、RPM、输入路径和其他元数据。 |
| `abnormal_probability` | `number` | 当前波形所观测诊断范围发生局部故障的模型概率分数，范围为 `[0,1]`。半直驱的诊断范围包含两个轴承。该字段是对训练标签 `is_observed_scope_abnormal` 的预测输出。 |
| `component_probabilities` | `object/null` | 当前诊断范围内四个已知部件各自的模型概率分数。半直驱表示两个轴承中至少一个轴承相应部件异常的分数，不区分具体物理轴承。部件诊断尚未训练时返回 `null`。 |
| `component_probabilities.outer_race` | `number` | 外环故障概率。 |
| `component_probabilities.inner_race` | `number` | 内环故障概率。 |
| `component_probabilities.rolling_element` | `number` | 滚动体故障概率。 |
| `component_probabilities.cage` | `number` | 保持架故障概率。 |

机型、测点位置、频率覆盖与分辨率、机理证据和模型版本保存在样本记录或内部诊断日志中，通过 `sample_id` 查询，不放入对外单波形输出。

### 11.2 第一阶段二分类输出

第一阶段尚未训练部件诊断头时：

```json
{
  "sample_id": "sample_001",
  "abnormal_probability": 0.92,
  "component_probabilities": null
}
```

此时仅返回 `abnormal_probability`；`component_probabilities` 必须为 `null`，不能返回未经训练的随机概率。任何阈值判定、告警分级和人工复核策略均由下游业务系统负责。

## 12. 数据集建设与切分

### 12.1 样本统计

数据量必须按以下维度统计：

- 机型；
- 诊断范围；
- 测点；
- 正常/故障；
- 四个已知部件；
- 标签来源；
- 转速区间；
- 独立故障过程。
- 独立 `range_id` 数量；
- 独立 `sample_group_id` 数量。

同一个故障过程切出的多个窗口不能视为多个完全独立故障事件。

### 12.2 故障过程、正常时间块与数据泄漏控制

业务方根据已记录的正常或异常起止时间，为每个机组—测点范围提供唯一 `range_id`。同一次持续故障下的多个测点异常范围共享 `fault_event_id`；结束边界可使用记录的故障结束时间、维修时间或轴承更换时间。

当前数据无法按独立故障事件同时构造训练集和验证集，因此第一阶段采用“同一开发范围内分层时间块随机切分”的弱监督基线。`sample_group_id` 是实际切分键，不作为模型输入，也不出现在单波形诊断结果中。规则如下：

- 对每个核心异常范围，以范围起点 `T_start` 和结束或更换时刻 `T_end` 计算相对位置 `range_progress=(acquisition_time-T_start)/(T_end-T_start)`；按 `[0, 1/3)`、`[1/3, 2/3)`、`[2/3, 1]` 分别记为 `early`、`middle`、`late`。一个月范围中三段大致对应前、中、后各约 10 天，但按实际时长等分，不强制每段样本数相同；
- `early/middle/late` 仅表示波形在核心异常范围中的时间位置，用于分层切分和分组评估，不代表真实故障严重程度，不作为模型输入；
- 核心异常范围默认按自然日形成互不重叠的 `sample_group_id`；采样不规则时按连续采集批次分块，相邻时间差大于 `3 ×` 该范围中位采样间隔时开始新块；每个相对位置至少需要 3 个非空时间块；
- 在 `early`、`middle`、`late` 各层内部，使用冻结的 `split_seed` 随机分配约 70% 时间块到训练集、约 30% 时间块到验证集。按时间块数计算 `n_val=max(1, round(0.3 × n_blocks))`，并保证至少 2 个训练块；随机的是时间块，不是单条波形；
- 正常范围不划分前、中、后，使用相同时间块形成原则，在完整正常范围内以固定 `split_seed` 按时间块约 70%/30% 随机划分；
- 同一条长波形切出的全部内部窗口必须保留在同一个 `sample_group_id`；任何时间块只能整体属于训练集或验证集；
- 半直驱同一故障过程或同一正常范围中，同一自然日或同一连续采集批次的 4 个测点共享相同切分结果，禁止将同一时刻的不同测点分别放入训练集和验证集；
- 同一异常范围可以同时贡献训练时间块和验证时间块，但各块保留相同的 `range_id` 和 `fault_event_id`。这种验证只能称为“同项目、同事件的分层时间块验证”，不是独立故障事件验证，也不是严格的未来时间外推验证；
- 半直驱开发项目的 4 个异常范围若属于同一次故障，验证结果同时按测点和单一 `fault_event_id` 汇总，不能记为 4 个独立事件；
- 双馈开发项目的 1 个正常范围和 1 个异常范围按相同规则切分，验证集仍与训练集共享项目和故障过程，结果可能偏乐观；
- 另一个项目或机组的范围整体保留为测试集，不再拆回训练或验证。半直驱测试目前同一测点具有 1 个正常范围和 1 个核心异常范围，双馈测试目前只有 1 个核心异常范围；
- 测试范围在模型结构、预处理、损失、融合方式和评估口径冻结前不得用于调参；
- 不属于已确认正常或异常范围的样本不得自动赋予监督标签，只能进入单独无监督清单。

因此，开发验证用于选择模型；半直驱测试用于检查跨机组正常/异常范围来源迁移，双馈测试用于检查跨项目异常侧迁移。半直驱正常测试范围不得参与开发选择，双馈仍缺少外部正常测试范围。

### 12.3 样本均衡

- 故障样本按 `range_id`、`fault_event_id` 和时间块 `sample_group_id` 分组采样，避免同一次持续故障的大量连续波形支配训练。
- 正常样本的 `fault_event_id` 通常为 `null`，按正常时间块的 `sample_group_id` 分组采样；长时间正常范围可以形成多个分组并分配到不同数据集。
- 对少数部件使用类别权重或 Focal Loss。
- 转速筛选规则必须只依据业务有效范围，不能依据测试结果反向选择。
- 未确认历史数据不能自动标为正常，应进入单独的无监督数据清单，可用于自监督预训练但不参与上述监督损失。

## 13. 训练策略

### 13.1 第一阶段：二分类基线与融合

- 使用开发项目正常范围和核心异常范围传播得到的单波形弱标签训练；验证集按第 12.2 节以固定 `split_seed` 从完整时间块中分层随机构造，禁止单波形随机划分。
- 训练采样按 `range_id` 和 `sample_group_id` 均衡，避免采样密集的某个测点或时间段主导损失；验证报告同时保留波形级、范围级和故障事件级结果。
- 从每条样本形成原始波形和普通谱/包络谱双通道频谱两条编码路径。
- 时域分支默认采用轻量多尺度 1D CNN，频谱分支默认采用浅层双通道 1D CNN；初期不使用 LSTM、Transformer、域适配、知识蒸馏或深层残差网络。
- 将归一化平均 RPM 作为融合阶段的一个标量输入，不设置独立 RPM 编码器。
- 从普通谱和包络谱提取一次四部件连续机理特征，并按四部件聚合后辅助总体二分类。
- 训练两路径完整谱形分支、共享机理 MLP、总体聚合、机理辅助头与正常/故障融合头；机理辅助头只用于训练监督和内部评估。
- 第一阶段记录 `q_global`、`g_global`、总体门控向量范数比、机理辅助概率，以及各部件 `q_c` 和特征覆盖情况；不计算尚未启用的部件门值 `g_c` 或部件概率。
- 暂不输出部件诊断。
- 在相同开发训练/验证切分上分别评估现有 FFT 机理规则（对比实验）、仅谱形模型和谱形加机理融合模型；模型冻结后才在跨项目异常测试范围上运行一次。

### 13.2 第二阶段：部件机理融合与定位

- 根据上游直接传入的四部件特征阶次和平均 RPM 换算 BPFO、BPFI、BSF、FTF 近似理论频率，将其作为频谱搜索锚点而不是分类输入。
- 复用第一阶段已提取的四个候选部件连续机理特征，不重复提取。
- 启用四部件独立输出头，将对应部件机理向量与谱形特征融合。
- 使用标签掩码兼容只有二分类标签的样本。

### 13.3 第三阶段：未知异常与少标签增强

- 使用大量无标签数据进行掩码频谱重建或对比预训练。
- 建立正常表征距离或域外检测分数。
- 只有后续补充独立验证数据后，才确定“未定位局部故障”和“待复核”规则；当前同事件时间块验证不用于声称该规则已跨事件成立。

### 13.4 第四阶段：连续转速与时频扩展

- 接入与振动波形严格同步的连续转速序列并统计单条波形内转速波动，用于评估平均 RPM 理论频率的误差和机理可靠度。
- 模型输入仍保持固定 Hz 普通频谱和包络频谱，不引入阶次谱或阶次跟踪。
- 对明显非平稳样本可专项验证 STFT 或 CWT 分支。
- 只有专项实验有稳定增益时，才将时频分支纳入生产模型。
## 14. 评估方案

### 14.1 二分类指标

开发验证集同时包含正常范围时间块和异常范围时间块，可以按传播后的弱标签计算：

- Accuracy、Balanced Accuracy；
- Precision、Recall、F1；
- PR-AUC 和 ROC-AUC；
- 混淆矩阵；
- 不同机型、测点和转速区间的分组指标；
- 核心异常验证集按 `early`、`middle`、`late` 分别报告异常范围阈值命中率（弱标签 Recall）以及 `abnormal_probability` 的 P50、P90，检查三个相对位置的表现是否失衡；

阈值型指标统一使用开发验证阶段确定的 `evaluation_threshold`：第一版在开发验证集上选择 F1 最大的阈值；模型和阈值选定后一起冻结，外部测试不得重新调阈值。评估程序按 `abnormal_probability >= evaluation_threshold` 得到预测异常标签，并计算：

```text
Accuracy = (TP + TN) / (TP + TN + FP + FN)
Balanced Accuracy = 0.5 × [TP / (TP + FN) + TN / (TN + FP)]
异常范围阈值命中率 = 异常范围内 abnormal_probability >= evaluation_threshold 的有效波形数 / 异常范围有效波形总数
```

异常范围阈值命中率等同于按范围传播弱标签计算的 Recall，因此简称“弱标签 Recall”；它不能解释为基于逐波形人工真值的真实 Recall。`evaluation_threshold` 只服务于离线指标计算，不改变第 11 节规定的模型概率输出，也不等同于生产告警阈值。若后续明确业务误报率目标，应在新的开发验证方案中按该目标重新确定阈值并生成新模型版本，不能利用测试集反向选择。

这些指标只衡量模型区分“正常时间范围波形”和“异常时间范围波形”的能力。由于异常范围内并非每条波形都必然表现出故障特征，它们不能解释为基于逐波形真实标签的诊断性能。除波形级指标外，还必须按 `range_id` 和 `fault_event_id` 报告分数分布，避免把同一事件的大量波形当成大量独立证据。

数据类别不平衡时，以 PR-AUC、Recall 和误报率为主要开发指标，不能只使用准确率。

半直驱外部测试同一测点具有 1 个正常范围和 1 个核心异常范围，可使用冻结的 `evaluation_threshold`，按范围传播弱标签报告 Accuracy、Balanced Accuracy、异常范围阈值命中率（弱标签 Recall）、特异度、误报率、混淆矩阵、ROC-AUC 和 PR-AUC，但只能解释为跨机组正常/异常范围来源可分性。双馈外部测试仍只有 1 个核心异常范围，只报告 `abnormal_probability` 分布、异常范围阈值命中率（弱标签 Recall）和专家复核，不能单独计算 Accuracy、Balanced Accuracy 或其他需要正常样本的完整二分类指标，也不能将弱标签 Recall 解释为逐波形真实 Recall。

### 14.2 部件定位指标

启用四部件诊断后评估：

- 每个部件的 Precision、Recall 、漏报率和 F1；
- Macro-F1、Micro-F1 和多标签 mAP；

当前范围传播只提供总体正常/异常弱标签，不能据此计算可信的部件定位指标。第 14.2 节仅在后续获得足够的逐波形或事件级可靠部件标签并重新制定切分方案后启用。


### 14.3 核心对比实验

核心对比分为三类，其中机理融合对比固定包含四个模型组：

1. **谱形分支与轻量结构对比**：以浅层双通道频谱 CNN 为最小深度学习基线，与“轻量多尺度时域 CNN + 浅层双通道频谱 CNN”比较，确认时域分支和多尺度卷积是否提供稳定增益；同时检查加入归一化平均 RPM 标量前后的二分类表现，防止模型利用转速与标签的偶然偏差。轻量 ResNet1D、注意力池化等结构仅在基础模型表现出稳定欠拟合时进入专项比较。
2. **机理融合四组对比**：在谱形结构确定后，使用完全相同的数据切分、训练轮次、随机种子集合和主要评价指标，固定比较以下四组：
   - A 组，仅完整谱形：`z_spec → AbnormalHead`；
   - B 组，仅机理：`z_phy_global → MechanismOnlyHead`；
   - C 组，直接拼接：`[z_spec, z_phy_global] → AbnormalHead`，不使用可靠度门控；
   - D 组，可靠度门控融合：使用第 9.3 节定义的 `q_global` 和 `g_global` 融合结构。

   四组同时报告开发验证集上的二分类性能、概率分数分布、机理特征缺失时的退化表现及分组指标。只有 D 组在正常验证时间块和异常验证时间块上稳定优于 A、C 组，并且没有因低可靠度机理证据增加误报或漏报时，可靠度门控才进入候选生产模型。B 组用于确认机理分支本身是否具有有效信息，不作为最终生产架构。部件定位启用后，以相同原则比较仅谱形、仅候选部件机理、直接拼接和候选级可靠度门控四组。
3. **少标签训练对比**：仅当确认标签不足时，比较有无自监督预训练，决定是否保留预训练阶段。

局部背景归一化、CWT 和内部窗口不列为固定消融项。阶次谱、角域重采样和短时阶次跟踪不属于本方案。只有数据分析暴露出底噪差异、间歇冲击、长波形或明显非平稳等具体问题时，才进行对应专项验证。

所有对比使用相同的开发训练/验证切分和主要评价指标，跨项目异常测试集不参与结构或超参数选择。模型冻结后再检查候选方案在跨项目异常测试范围上的异常侧表现；由于测试缺少正常样本，不能要求它单独证明新增模块未增加误报。只有开发验证显示稳定收益、跨项目异常侧结果没有明显失效，且增加的计算与维护成本可接受时，新增模块才进入后续试运行。

### 14.4 门控使用评估

除诊断指标外，门控模型必须单独报告：

- `q_global`、`g_global` 和门控后机理/谱形向量范数比的总体分布；
- 按机型、测点、转速区间和标签分组的门值分布；
- `q_global` 较高但 `g_global` 长期接近 0 的样本比例；
- 机理不可用时退化为仅谱形判断的样本比例及其性能；
- 门控融合相对于仅谱形模型改变预测方向的样本数量，并对其中的正确修正和错误修正分别统计；
- 机理辅助头的 PR-AUC、Recall 及正常/故障概率分数分离情况。

门控使用评估只用于验证融合机制和发现异常行为，不设置脱离诊断指标的固定门值目标，也不能为了提高门控使用率而强迫模型放大机理分支。

### 15.1 兼容现有机理结果

现有机理算法对正常/故障的业务估计分辨能力约为 80%，对四部件的估计分辨能力约为 50%。这些数值说明机理证据应同时服务总体二分类和部件定位，但只是架构依据，必须在统一、无数据泄漏的独立测试集上重新验证。

## 16. 运行接口与人工配置

### 16.1 输入测点元数据

`machine_type` 和 `sensor_position` 用于标识当前波形的诊断范围，不用于查找四部件理论阶次：

```json
{
  "machine_type": "dfig",
  "sensor_position": "drive_end"
}
```

半直驱的 `sensor_position` 固定取 `12点`、`3点`、`6点`、`9点`。23#应覆盖全部四个测点；13#的具体测点从文件名解析，正常与异常文件的解析结果必须一致。四部件特征阶次由上游在当前样本中直接提供。第一版不将 `machine_type` 或 `sensor_position` 输入总体异常头或四部件分类头，只用于数据筛选、分组评估、结果解释和日志查询。

文件名去掉扩展名后按最右侧三个下划线字段解析：

```text
<设备与测点描述>_<fs>Hz_<rpm>_<YYYYMMDDhhmmss>
```

例如 `广东能源尚洋湾海风场*23#*发电机3点径向_25600Hz_65.8824_20231004171053` 解析为 `sensor_position=3点`、`sampling_rate_hz=25600`、`rpm=65.8824`、`acquisition_time=2023-10-04 17:10:53`。半直驱测点只从前缀中的 `发电机(12点|3点|6点|9点)` 提取，避免项目或机组名称中的其他数字干扰。波形文件数量和相邻采样间隔由样本清单按机组、测点和范围自动统计。

### 16.2 人工可调配置

运行时允许人工调整的配置仅包括 RPM 有效范围：

```json
{
  "rpm_range": {
    "min": 0.0,
    "max": 0.0
  }
}
```

示例中的 `0.0` 仅表示字段格式，实际范围由业务工况确定。开发阶段由本地样本清单构建器或数据加载器使用该范围筛选；生产阶段由数据库查询使用同一范围，模型入口继续做合法性兜底检查。

## 17. 单波形推理流程

```text
1. 读取单列原始波形、样本元数据和直接传入的四部件特征阶次
2. 校验采样率和平均 RPM，并按固定的 `rpm_range` 筛选
3. 校验 `sensor_position` 及各部件阶次
4. 对原始波形执行去均值，形成时域输入
5. 由同一原始波形生成普通线性幅值频谱和包络线性幅值频谱，并按通道堆叠形成双通道频谱输入
6. 使用训练阶段固定的范围缩放平均 RPM，得到单个归一化标量
7. 分别编码原始波形和双通道频谱，与 RPM 标量融合得到 `z_spec`
8. 按平均 RPM / 60 × 对应阶次值换算理论频率，将其作为搜索锚点，从频谱一次性提取四部件连续机理特征；理论频率及实际峰值绝对 Hz 位置不直接输入机理 MLP
9. 聚合四部件机理证据，生成总体机理向量
10. 执行总体机理可靠度门控，与 `z_spec` 融合后输出异常概率
11. 使用总体机理辅助头计算 `p_phy_aux` 并写入内部日志，不参与对外输出
12. 若部件诊断头已启用：执行部件机理编码、候选级可靠度门控并输出四部件概率
```

第一阶段不启用部件诊断头时，仍提取四部件机理特征并聚合用于总体二分类，继续执行第 10、11 步并跳过第 12 步，返回 `component_probabilities=null`。

异常处理原则：

- 某部件特征阶次缺失或非法：该部件的机理定位标记为不可用，其他有效部件和完整谱形分支继续运行。
- `sensor_position` 不符合对应机型枚举：记录元数据错误，但不通过其他字段重新查询阶次。
- 理论故障频率超出有效频带或当前分辨率不足：保留完整频谱分支结果，将对应部件的机理特征标记为不可用或低可靠度。

## 18. 内部解释信息

以下信息保存在内部诊断日志中，不属于第 11 节定义的对外单波形输出。每个已知部件至少保留：

- 特征阶次及按平均 RPM 换算的近似理论频率 Hz；
- 1～5 阶实际峰值位置；
- 峰值与局部背景之比；
- 频率偏差；
- 有效谐波数量；
- 边带证据；
- 部件机理可靠度 `q_c`；
- 第二阶段启用部件诊断头后保存机理分支门值 `g_c` 和最终部件概率；第一阶段不生成这两个字段。

总体融合还应保留 `q_global`、`g_global`、门控后机理/谱形向量范数比、机理辅助概率、门控融合前后异常 logit 差值，以及是否退化为仅谱形判断。训练和评估阶段应汇总这些字段的分布；生产阶段按模型版本、机型、测点和转速区间监控分布漂移。

内部解释信息用于算法调试和专家复核，可通过 `sample_id` 关联，但不应将单个峰值直接描述为确定故障原因。模型概率和机理证据必须分别记录。

## 19. 风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 将范围传播标签误认为逐波形真值 | 高估模型的真实单波形诊断能力 | `label_source` 明确记录 `normal_time_range`/`abnormal_time_range`，所有指标注明为弱标签范围可分性 |
| 异常范围内部分波形没有明显故障特征 | 异常弱标签噪声导致模型学习困难 | 按范围和时间块均衡采样，检查分数分布并对高分、低分样本做专家抽样复核 |
| 将未知范围样本自动标为正常 | 增加漏报并污染正常类别 | 只有已确认正常范围传播 `false`；其他样本进入无监督清单 |
| 同一范围相邻波形或同一时刻不同测点跨训练/验证集 | 验证结果因时间相关性而虚高 | 只随机分配完整时间块；同一故障事件同一日期或采集批次的多测点共享切分结果；明确当前验证是同项目、同事件的分层时间块验证，不是独立事件验证 |
| 半直驱 4 个测点范围被当成 4 个独立故障事件 | 夸大有效样本量 | 共享同一故障过程的范围使用同一 `fault_event_id`，按测点和事件两个层级汇总 |
| 双馈跨项目测试只有异常范围 | 无法评估双馈独立正常数据上的误报 | 双馈测试只报告异常侧分数和覆盖情况；半直驱使用已有正常范围评估跨机组误报 |
| 半直驱测试只提供 1 个测点 | 结论无法覆盖该机组全部 4 个测点 | 结论限定到已提供测点，后续补齐其他测点异常及正常测试范围 |
| 只有平均 RPM，采样期内转速变化未知 | 由平均 RPM 换算的理论频率可能偏移或展宽 | 第一版仅使用 Hz 频谱；扩大有依据的搜索窗、限制机理可靠度，缺少稳定性依据时不输出强负证据 |
| 直接传入的故障特征阶次缺失或错误 | 部件定位证据错误或不可用 | 校验四个阶次为有限正数，单个无效部件使用缺失掩码，不执行回查 |
| 理论故障频率超出有效频带或分辨率不足 | 无法可靠搜索目标峰值 | 将对应机理特征标记为不可用或低可靠度，不影响完整频谱分支判断 |
| 传感器测量方向不确定 | 幅值分布漂移 | 不使用依赖测量方向的多测点幅值比、相位、互谱或相干性特征，并按 `sensor_position` 分组评估 |
| 强制四部件分类 | 其他局部故障被误定位 | 独立异常头和“未定位局部故障”状态 |
| 独立故障事件过少 | 模型过拟合项目、机组或事件特征 | 保持轻量模型，按 `range_id`/`fault_event_id` 报告结果并持续补充独立项目数据 |

## 21. 结论

第一版采用单测点完整波形独立诊断，不进行多测点融合或阶次谱处理。由于没有逐波形专家标签，上线后一个自然月正常范围内的有效波形统一标为正常，故障结束时间向前一个自然月核心异常范围内的有效波形统一标为异常，形成单波形弱监督训练目标。模型由轻量时域分支、普通谱/包络谱双通道分支和总体机理门控组成；理论故障频率只负责定位搜索，连续观测证据才进入机理编码器。

总体异常头与四个参数独立的部件头分离，机理无效时均可退化为谱形判断。总体机理辅助头保留在生产模型中用于内部监控，不参与对外输出；门控结构只有在四组对比中显示稳定收益时才上线。

第一版不输入 `machine_type` 或 `sensor_position`，不输出 `confidence`，仅输出 `abnormal_probability` 和已启用的四部件概率，不在模型内生成正常、复核、故障或部件诊断结论。开发项目的核心异常范围按前、中、后三个相对时间位置分层，再以完整时间块约 70%/30% 随机划分训练和验证；正常范围直接按完整时间块约 70%/30% 随机划分。半直驱另一机组的正常与核心异常范围在方案冻结后用于跨机组测试，双馈另一项目的核心异常范围用于异常侧测试。当前验证仍共享项目和故障过程，双馈测试又缺少正常范围，因此结论必须限定为弱标签可行性和有限迁移结果，不能宣称已完成充分的独立分类性能验证。
