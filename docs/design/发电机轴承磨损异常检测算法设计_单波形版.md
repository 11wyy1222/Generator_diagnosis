# 发电机轴承磨损异常检测算法设计（单波形版）

## 1. 文档目的

本文档定义双馈和半直驱发电机轴承振动异常检测算法。方案适配当前数据现状：数据方能够提供正常时间范围和异常时间范围，但没有逐条波形故障标签；异常时间范围只保证其中存在一条或一部分异常波形，不表示范围内每条波形都异常。

第一版采用正常数据建模，不使用异常范围训练监督分类器。正常范围统一取正常数据上线时间起一个自然月：开发项目的正常时间范围先形成不重叠的完整时间块，再以固定随机种子按约 70%/30% 随机划分正常训练集和正常验证集；开发项目的完整异常时间范围作为异常验证集；另一个项目或机组的完整异常时间范围作为模型冻结后的外部异常测试，若该对象具有维修后正常范围，则同时作为外部正常测试。模型每次只输入一个测点的一条完整振动波形，并只对外输出该波形的 `abnormal_probability`。该字段表示相对于正常参考分布的归一化异常程度，不输出正常、复核、故障等业务结论。

第一版不执行多测点融合，不在模型内进行多波形 Top-K 聚合，不设置故障部位标签、分类头或输出。时间范围只用于组织数据、选择正常训练数据、进行弱标签评估以及按异常分数排序供专家复核。

## 2. 已确认的业务与数据边界

### 2.1 机型和测点

- 双馈机型使用驱动端或非驱动端测点；一条波形只对应一个测点。
- 半直驱开发机组 23# 的 4 个正式测点为 `12点`、`3点`、`6点`、`9点`。半直驱测试机组 13# 的具体测点从文件名解析，并必须属于同一枚举。
- 每个测点独立建立正常参考和计算异常分数，不在模型内融合不同测点。
- `machine_type` 和 `sensor_position` 用于数据筛选、正常参考分组、评估和日志查询，不直接输入异常评分头。

### 2.2 标签粒度

标签属于“机组—测点—时间范围”，不是单条波形标签：

```text
is_observed_scope_abnormal = false
→ 专家确认该测点的这个时间范围内没有观察到异常波形

is_observed_scope_abnormal = true
→ 专家确认该测点的这个时间范围内至少存在一条或一部分异常波形
```

异常范围标签不能复制给范围内的每条波形。正常范围只有在满足上述 `false` 语义时，范围内通过准入检查的波形才能用于正常模型训练。

### 2.3 当前数据能力边界与分配

当前数据按机型分别组织，两个机型之间不混合训练、验证或统计指标：

| 机型 | 开发项目（训练与验证） | 外部测试 | 数据解释 |
|---|---|---|---|
| 半直驱 | 1 个项目、1 台机组、4 个测点；共 4 个正常范围和 4 个完整异常范围 | 同项目另一台机组的 1 个测点，具有 1 个维修后正常范围和 1 个完整异常范围 | 4 个测点范围是同一机组上的相关观测，不是 4 个独立故障事件；外部测试属于跨机组而非跨项目 |
| 双馈 | 1 个项目、1 台机组、1 个测点；1 个正常范围和 1 个异常范围 | 另一个项目目前只有 1 个测点的 1 个异常范围 | 开发侧只有 1 个正常范围和 1 个异常范围，事件多样性很低 |

- 开发项目的正常范围以完整时间块为单位，使用固定随机种子按约 70%/30% 随机划分后用于正常模型训练和正常验证；禁止单波形随机拆分。
- 开发项目的异常范围不参与模型拟合，只用于模型选择、融合方案比较和异常案例验证。
- 外部测试范围在模型结构、预处理、参考分组和融合权重冻结前不得查看测试结果或据此调参。
- 半直驱外部测试同时包含维修后一个自然月正常范围和完整异常范围，可初步评估跨机组误报；双馈外部测试仍只有异常范围，不能独立完成正常误报能力评估。
- 现有异常事件数量不足以证明跨事件泛化能力；半直驱测试也只能证明当前已提供测点上的表现，不能代表该机组全部 4 个测点。

## 3. 总体算法架构

```text
单测点的一条原始波形
├─ 去均值后的完整波形
│  → 轻量时域编码器 → z_raw ──────────────────────┐
│                                                   │
├─ 普通线性幅值频谱与包络线性幅值频谱             │
│  → 双通道频谱编码器 → z_spectrum ────────────────┤
│                                                   │
└─ 归一化平均 RPM 标量 ────────────────────────────┤
                                                    ↓
                         深度谱形融合特征 z_deep
                                                    │
              正常表征中心和正常协方差/距离模型 ───┤
                                                    ↓
                                      deep_anomaly_score

现有 FFT 机理算法的逐波形连续输出
→ 内部总体聚合
→ 相对于同测点正常参考的稳健偏离
→ mechanism_anomaly_score

deep_anomaly_score 与 mechanism_anomaly_score
→ 分别按正常训练分布归一化
→ 固定权重融合
→ abnormal_probability
```

总体原则：

1. 原始波形和频谱表征负责发现数据中偏离正常模式的形态，不依赖异常逐波形标签。
2. 现有机理算法只提供连续观测证据，不使用其布尔报警结果作为真实标签。
3. 两类异常分数先独立建立正常参考，再进行固定权重融合；第一版不使用需要异常标签训练的门控网络。
4. 机理证据缺失时，模型退化为仅使用深度谱形异常分数。

## 4. 数据清单与范围标签

### 4.1 单波形清单

单波形记录只保存输入和追溯信息，不从异常范围继承逐波形标签：

```json
{
  "sample_id": "sample_001",
  "waveform_path": "[waveform_path]",
  "acquisition_time": "2024-01-01 10:20:30",
  "sampling_rate_hz": 25600.0,
  "rpm": 215.0,
  "rpm_source": "filename",
  "machine_type": "semi_direct",
  "turbine_id": "turbine_001",
  "sensor_position": "3点",
  "range_id": "fault_range_001_p03",
  "sample_group_id": "fault_event_001"
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `sample_id` | 单条波形唯一标识，也是模型输出关联键 |
| `waveform_path` | 单列原始振动波形路径或统一数据引用 |
| `acquisition_time` | 波形采集时间 |
| `sampling_rate_hz` | 采样率，单位 Hz |
| `rpm` | 当前波形对应的平均转速 |
| `rpm_source` | 转速来源，当前通常为 `filename` |
| `machine_type` | `dfig` 或 `semi_direct` |
| `turbine_id` | 机组标识，用于参考分组和防止数据泄漏 |
| `sensor_position` | 当前波形所属测点 |
| `range_id` | 当前波形所属的测点时间范围 |
| `sample_group_id` | 数据切分分组键，不作为模型输入 |

不记录 `signal_quality_level`。空数据、长度错误、采样率错误、无法执行 FFT、严重削顶或饱和等情况由数据加载和预处理阶段直接拒绝，并写运行日志。

文件名去掉扩展名后按最右侧三个下划线字段解析：

```text
<设备与测点描述>_<fs>Hz_<rpm>_<YYYYMMDDhhmmss>
```

例如 `广东能源尚洋湾海风场*23#*发电机3点径向_25600Hz_65.8824_20231004171053` 解析为 `sensor_position=3点`、`sampling_rate_hz=25600`、`rpm=65.8824`、`acquisition_time=2023-10-04 17:10:53`。半直驱测点只从前缀中的 `发电机(12点|3点|6点|9点)` 提取。`waveform_length=N` 读取波形文件第一列长度；同一机组、同一测点长度不一致的文件从建模数据集剔除并登记，但不覆盖原始文件。波形数量和相邻采样间隔由生成后的样本清单自动统计。

### 4.2 测点时间范围清单

正常和异常标签保存在独立的范围清单中：

```json
{
  "range_id": "normal_range_001_p03",
  "fault_event_id": null,
  "sample_group_id": "normal_turbine_001_p03_202301",
  "machine_type": "semi_direct",
  "turbine_id": "turbine_001",
  "sensor_position": "3点",
  "range_start": "2023-01-01 00:00:00",
  "range_end": "2023-01-31 23:59:59",
  "is_observed_scope_abnormal": false,
  "label_source": "expert_review"
}
```

```json
{
  "range_id": "fault_range_001_p03",
  "fault_event_id": "fault_event_001",
  "sample_group_id": "fault_event_001",
  "machine_type": "semi_direct",
  "turbine_id": "turbine_001",
  "sensor_position": "3点",
  "range_start": "2023-05-14 00:00:00",
  "range_end": "2024-01-06 04:59:19",
  "is_observed_scope_abnormal": true,
  "label_source": "expert_review"
}
```

规则：

- `false` 范围中的有效波形可作为正常参考数据。
- `true` 范围中的波形不逐条赋值为 `true`，不进入正常参考拟合。
- 无法确认范围结论的数据不进入正常模型训练和正式弱标签评估，可单独保留用于后续复核。
- `label_source` 只用于追溯，不作为模型输入。
- 同一故障过程下不同测点可以有不同 `range_id`，但必须共享同一个 `fault_event_id` 和 `sample_group_id`。

## 5. 数据准入与信号预处理

### 5.1 内部准入检查

进入算法前执行以下检查：

- 文件存在且能够读取为有限数值序列；
- `N` 为每条波形第一列长度；同一机组、同一测点只保留目标长度一致的波形，长度不一致文件从建模数据集剔除并登记；
- 采样率能够解析且大于 0；
- 平均 RPM 能够解析且位于统一 `rpm_range`；
- 波形至少包含执行 FFT 所需的有效点数；
- 严重削顶、饱和、长时间恒定或明显通信填充值的数据被拒绝。

检查结果只进入运行日志，不进入样本字段和模型特征。

### 5.2 时域输入

```text
原始波形
→ 去均值
→ 使用正常训练集确定的固定全局缩放系数
→ 时域编码器
```

第一版使用完整波形，不对同一条波形再次切窗。禁止逐样本最大值归一化或逐样本标准化，以免删除幅值异常信息。

### 5.3 普通谱和包络谱输入

普通频谱：

```text
去均值后的原始波形
→ Hann 窗
→ 单边 FFT
→ 截取统一有效频带
→ 插值到固定 Hz 网格
→ 普通线性幅值谱
```

包络频谱：

```text
去均值后的原始波形
→ Hilbert 包络
→ 去除包络直流分量
→ Hann 窗和单边 FFT
→ 截取统一有效频带
→ 插值到相同固定 Hz 网格
→ 包络线性幅值谱
```

两个频谱按通道维堆叠：

```text
spectrum_input.shape = [2, frequency_bin_count]
spectrum_input[0] = fft_spectrum
spectrum_input[1] = envelope_spectrum
```

第一版使用线性幅值，不执行逐样本能量归一化。若数值范围需要缩放，只允许使用正常训练集拟合并固定的全局缩放参数。

### 5.4 RPM 输入

平均 RPM 使用正常训练集确定的固定范围缩放：

\[
rpm_{scaled}=\frac{rpm-rpm_{min}}{rpm_{max}-rpm_{min}}
\]

缩放后的 RPM 作为谱形融合阶段的一个标量输入，用于减少正常工况变化被误判为异常的风险。RPM 不设置独立深层编码器。

## 6. 现有机理算法的复用方式

### 6.1 可复用的逐波形连续输出

现有工程能够对单条波形生成普通频谱和包络频谱的候选峰值、峰值位置、背景中位数以及连续峰背景比。第一版复用以下信息：

- `m_ArrMaxPoint_en` 和 `m_ArrMaxPoint` 中的峰值及频线位置；
- `mid_en` 和 `mid` 背景中位数；
- 批处理产生的逐波形 `envelope_values` 和 `fft_values`；
- 与当前波形精确对应的采集时间、路径和 RPM。

现有布尔字段和最终报警字段不作为训练标签，也不直接替代 `abnormal_probability`。原因是当前布尔结果包含工程规则、候选去重和批量汇总逻辑，不等价于逐波形人工确认标签。

### 6.2 总体机理异常向量

所有候选峰值连续证据只在内部聚合为总体机理向量，不形成类别输出。建议至少包含：

- 包络谱候选证据的最大值、均值和高分位数；
- 普通频谱候选证据的最大值、均值和高分位数；
- 有效谐波数量的总体统计；
- 峰值相对于搜索锚点的偏差统计；
- 普通谱与包络谱证据一致性；
- 证据是否可用的内部有效标记。

对每个机型、测点和 RPM 区间，使用正常训练数据拟合各连续证据的中位数和 MAD：

\[
z_{robust}=\frac{\log(1+E)-Median_{normal}}
{1.4826\times MAD_{normal}+\epsilon}
\]

总体机理异常分数由有效证据的稳健偏离聚合得到。证据缺失时不填 0 冒充正常，而是从当前融合权重中移除。

### 6.3 批处理输出需要补齐的追溯字段

为支持离线建模和专家排序，机理批处理结果需要逐条保留：

```text
processed_sample_id
processed_src_path
processed_time
processed_rpm
envelope_values
fft_values
mid_en
mid
```

当前 `run_full()` 默认只分析最近少量记录，并将逐波形连续证据沿记录维求和。用于数据集建设时应调用全量批处理或增加独立特征导出入口，不能使用求和结果替代逐波形记录。

## 7. 深度正常表征模型

### 7.1 轻量编码结构

第一版保持轻量结构：

- 时域分支：轻量多尺度 1D CNN；
- 频谱分支：浅层双通道 1D CNN；
- 池化：时域分支和频谱分支均使用 8 段自适应分段池化；
- 融合：拼接 `z_raw`、`z_spectrum` 和归一化 RPM 后使用小型 MLP；
- 初期不使用 LSTM、Transformer、深层残差网络、域适配或知识蒸馏。

8 段自适应分段池化将卷积特征沿时间轴或频率轴划分为 8 个区域并分别池化，在输出维度固定的同时保留粗粒度位置分布。第一版不使用整轴全局平均池化，避免丢失间歇冲击所在时段和谱峰所在频段；轻量注意力池化仅作为后续专项对比，不作为默认结构。

### 7.2 正常表征训练

训练只使用 `is_observed_scope_abnormal=false` 范围内通过准入检查的波形。

建议分两步：

1. 使用正常波形执行轻量重建或一致性预训练，避免编码器塌缩；
2. 在融合特征上拟合正常中心和收缩协方差，形成正常距离模型。

可使用以下训练目标：

\[
L_{normal}=L_{reconstruction}+\lambda_d\lVert z_{deep}-c\rVert_2^2
\]

其中 (c) 由正常训练特征初始化并在训练过程中固定或缓慢更新。异常范围不参与该损失。

### 7.3 深度异常分数

对当前波形的融合特征计算相对于正常参考的距离：

\[
d_{deep}=(z_{deep}-\mu)^T\Sigma_{shrink}^{-1}(z_{deep}-\mu)
\]

如保留重建解码器，可将重建误差作为第二项：

\[
s_{deep}=\alpha d_{deep}+(1-\alpha)e_{reconstruction}
\]

第一版的系数使用预先固定值，并在正常验证集和少量异常范围案例上检查稳定性，不使用现有少量异常范围拟合复杂参数。

## 8. 异常分支定义

模型只保留两类互补的异常证据：

- `deep_anomaly_score`：由正常波形表征模型给出的数据驱动异常程度；
- `mechanism_anomaly_score`：由当前波形的普通谱、包络谱和理论故障频率邻域证据给出的机理异常程度。

两类分数都只使用正常训练数据建立参考尺度，不再引入第三类统计量分支。

## 9. 异常分数融合与归一化

### 9.1 分支分数归一化

`deep_anomaly_score` 和 `mechanism_anomaly_score` 的量纲不同。每个分支都使用正常训练分布转换为可比较的异常百分位分数：

\[
u_j=F_{normal,j}(s_j)
\]

其中 (F_{normal,j}) 为该分支在正常训练数据上的经验累积分布函数。分数越大，表示相对于正常参考越异常。

### 9.2 固定权重融合

第一版使用非负固定权重：

\[
A=\frac{\sum_j m_jw_ju_j}{\sum_jm_jw_j}
\]

其中 (m_j\in\{0,1\}) 表示分支是否有效，(w_j\ge0)。默认初始权重为：

```text
w_deep = 0.625
w_mechanism = 0.375
abnormal_probability = A
```

权重只允许使用正常验证尾部和开发异常验证范围比较后调整；不使用少量异常范围训练门控权重。机理分支无效时退化为 `abnormal_probability = u_deep`。

这里的 `abnormal_probability` 是接口名称，表示单条波形相对于正常分布的归一化异常程度，不宣称是经过充分正负监督训练得到的统计故障概率。

## 10. 训练、验证和数据切分

### 10.1 正常训练集

- 仅使用专家确认的 `false` 范围。
- 开发项目的每个正常时间范围先按采集时间排序，默认按自然日形成不重叠的 `sample_group_id`；采样不规则时按连续采集批次分块，相邻时间差大于 `3 ×` 该范围中位采样间隔时开始新块。
- 冻结 `split_seed=2026`，以完整 `sample_group_id` 为随机单位，将约 70% 时间块分配到正常训练集、约 30% 分配到正常验证集。按时间块数计算 `n_val=max(1, round(0.3 × n_blocks))`，并保证至少 2 个训练块；禁止按单波形随机打散。
- 半直驱同一机组同一自然日或同一连续采集批次的 `12点/3点/6点/9点` 共享切分结果，禁止同一时段不同测点跨训练集和验证集。
- 切分后按测点和 RPM 分箱检查训练/验证覆盖；若某个具有足够时间块的 RPM 分箱只出现在一侧，则使用相同 `split_seed` 在完整时间块层面执行分层随机划分。不得根据模型指标反复挑选切分。
- 每个正常范围至少需要 3 个非空时间块；划分结果写入并冻结 `split_manifest.jsonl`，所有模型和对比实验复用同一清单。
- 正常训练集用于拟合预处理缩放、深度编码器、正常中心、协方差、中位数、MAD 和经验分布。
- 正常验证集必须来自未参与任何参数或正常参考拟合的时间块，用于观察正常分数尾部、选择模型和比较融合方案。
- 半直驱开发侧使用 4 个测点的正常范围完成上述联动切分；双馈开发侧使用其 1 个正常范围完成上述切分。联动切分只用于防止泄漏，不改变不同测点正常参考独立管理的规则。

### 10.2 异常范围

- 异常范围内的波形不参与正常模型训练。
- 不将范围标签复制为逐波形 `true`。
- 开发项目中的异常范围构成异常验证集：半直驱为同一机组 4 个测点的 4 个异常范围，双馈为 1 个测点的 1 个异常范围。它们可用于模型选择、固定权重比较和专家复核，但不能反向参与编码器、正常参考或分数归一化拟合。
- 同一个 `fault_event_id` 的全部测点和波形必须进入同一个验证或测试集合。半直驱的 4 个测点范围共享同一故障事件时，应按 1 个事件报告，不得按 4 个独立事件扩大样本量。
- 另一个项目或机组的范围构成模型冻结后的外部测试集：半直驱同一测点具有 1 个维修后正常范围和 1 个完整异常范围，双馈目前只有 1 个异常范围。
- 跨项目测试测点必须具有明确的 `sensor_position`，并能匹配开发侧已建立的同机型、同测点位置正常参考；若位置不匹配或元数据不确定，只能作为探索性案例，不能并入正式测试汇总。
- 测试范围不得用于选择网络结构、预处理参数、RPM 分组、融合权重或 `evaluation_threshold`。
- 当前异常范围数量少，不能通过随机拆分其中的单波形制造独立事件，也不能据此宣称已完成充分的跨事件泛化验证。

### 10.3 自监督数据边界

第一版优先只使用确认正常波形训练正常编码器。若后续希望使用未确认历史波形进行通用自监督预训练，必须与正常参考拟合分离：未确认数据可以预训练编码器，但正常中心、协方差和分数分布仍只能使用确认正常数据拟合。

## 11. 评估方案

### 11.1 当前可计算的指标

由于没有逐波形异常标签，不能计算可信的逐波形 Precision、Recall、F1 或混淆矩阵。当前至少报告：

- 正常训练范围、正常验证范围、开发异常验证范围和跨项目异常测试范围的单波形分数分布；
- 每个机型、机组、测点和 RPM 区间的分位数曲线；
- 开发异常验证范围中高分波形相对于匹配正常验证范围的富集程度；
- 开发异常验证范围和外部异常测试范围的异常范围阈值命中率（范围级弱标签 Recall）；
- 开发异常验证范围和跨项目异常测试范围 Top-N 波形经专家复核后的命中情况；
- 不同独立故障事件之间的案例一致性；
- 输入证据缺失时各分支的退化表现。

第一版对每个匹配的正常参考组，默认使用正常验证集 `abnormal_probability` 的 P95 作为离线评估阈值，并在运行外部测试前冻结：

```text
evaluation_threshold = P95(abnormal_probability of matched normal validation group)
异常范围阈值命中率 = 异常范围内 abnormal_probability >= evaluation_threshold 的有效波形数 / 异常范围有效波形总数
```

该指标在计算形式上等同于临时传播范围标签得到的 Recall，因此称为“范围级弱标签 Recall”；由于异常范围内并非每条波形都有异常表现，它不能解释为基于逐波形人工真值的真实 Recall。`evaluation_threshold` 仅用于离线评估，不改变模型对外仅输出 `abnormal_probability` 的接口，也不是生产告警阈值。开发异常范围可用于比较模型，但不得为了提高命中率单独降低阈值；外部测试不得参与阈值选择。

把异常范围内所有波形都当作正样本计算的 ROC-AUC 或 PR-AUC，只能解释为“异常时间范围与正常时间范围的分布可分性”，不能解释为逐波形故障分类性能。

半直驱外部测试同时具有维修后正常范围和完整异常范围，可报告正常范围高分率、特异度、异常范围阈值命中率（范围级弱标签 Recall）和正常/异常范围来源可分性，但因缺少逐波形真值，不能解释为真实逐波形诊断性能。双馈外部测试仍只有异常范围，不能单独计算特异度、误报率、完整混淆矩阵、ROC-AUC 或 PR-AUC，只报告异常分数分布、异常范围阈值命中率（范围级弱标签 Recall）和专家复核结果；该弱标签 Recall 不能解释为逐波形真实 Recall。

### 11.2 核心对比实验

固定比较以下三组：

1. A 组：仅深度时域/频谱正常表征异常分数；
2. B 组：仅现有机理连续证据异常分数；
3. C 组：深度和机理异常分数固定权重融合。

所有组使用相同的正常训练范围、正常验证范围和开发异常验证范围。只有 C 组在不同测点和开发异常验证范围上稳定优于 A 组，并且没有明显增加正常高分尾部时，才保留融合方案。跨项目异常测试范围只在模型和权重冻结后评估，不参与三组方案选择。

另外比较：

- 仅频谱编码器与时域加频谱编码器；
- 是否输入归一化 RPM；
- 不同正常参考分组粒度；
- 不同全局缩放方式；
- 编码距离与重建误差的组合方式。

## 12. 单波形输入与输出接口

### 12.1 输入

```json
{
  "sample_id": "sample_001",
  "waveform_path": "[waveform_path]",
  "sampling_rate_hz": 25600.0,
  "rpm": 215.0,
  "machine_type": "semi_direct",
  "turbine_id": "turbine_001",
  "sensor_position": "3点"
}
```

输入只对应一条波形。模型不接收时间范围标签、其他测点波形或同一范围内的其他样本。

### 12.2 对外输出

```json
{
  "sample_id": "sample_001",
  "abnormal_probability": 0.86
}
```

字段说明：

| 字段 | 类型 | 含义 |
|---|---|---|
| `sample_id` | `string` | 当前波形唯一标识 |
| `abnormal_probability` | `number` | 当前波形相对于正常参考分布的归一化异常分数，范围 `[0,1]` |

模型不对外输出阈值判断、告警等级、人工复核建议、故障位置、置信度或内部机理证据。

### 12.3 内部日志

内部日志至少保存：

```text
sample_id
model_version
normal_reference_version
deep_anomaly_score
mechanism_anomaly_score
abnormal_probability
各分支有效标记
拒绝原因（仅输入未通过时）
```

内部日志用于算法调试、分布漂移检查和专家按分数排序，不属于对外模型输出。

## 13. 单波形推理流程

```text
1. 读取单列原始波形和元数据
2. 检查文件、长度、有限值、采样率、RPM 和严重信号失真
3. 根据 machine_type、sensor_position 和 RPM 选择对应正常参考版本
4. 波形去均值并使用训练阶段固定的全局缩放参数
5. 生成普通线性幅值频谱和包络线性幅值频谱
6. 编码原始波形和双通道频谱，与归一化 RPM 融合得到 z_deep
7. 计算 z_deep 相对于正常表征中心的深度异常分数
8. 调用或复用现有 FFT 机理连续输出，计算总体机理异常分数
9. 对两个有效分支分数执行正常参考归一化和固定权重融合
10. 输出 sample_id 与 abnormal_probability
11. 将分支分数和参考版本写入内部日志
```

机理分支不可用时，不使用 0 冒充正常，模型退化为仅使用深度异常分数。时域和频谱主分支不可用时直接拒绝输入。

## 14. 与现有工程衔接

现有工程已经具备普通频谱和包络频谱计算、候选峰值搜索、连续峰值历史以及统一诊断结果结构。建议保留现有计算逻辑，新增以下模块：

```text
waveform_manifest.py
  单波形清单与范围清单关联、时间和测点校验

waveform_preprocessor.py
  准入检查、去均值、固定缩放、普通谱和包络谱生成

normal_reference.py
  按机型、测点和 RPM 管理正常中心、协方差、中位数、MAD 和经验分布

mechanism_evidence_adapter.py
  将现有逐波形机理输出整理为总体连续证据，不生成类别结论

bearing_anomaly_model.py
  轻量时域编码器、双通道频谱编码器、正常表征和深度异常分数

anomaly_score_fusion.py
  分支分数归一化、缺失分支处理和固定权重融合

bearing_anomaly_inference.py
  单波形推理和精简输出
```

现有批处理接口需要增加成功处理记录的 `sample_id`、路径、时间和 RPM，避免文件读取失败后输出数组与输入路径错位。用于训练数据导出时必须保留逐波形连续矩阵，不能只保留沿记录维的求和结果。

## 15. 风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 将异常范围标签复制给每条波形 | 大量错误正标签 | 异常范围不参与逐波形监督训练 |
| 正常范围实际含有异常或采集故障 | 正常参考被污染 | 先执行内部准入检查，检查正常分数尾部并进行专家抽样复核 |
| 正常工况覆盖不足 | 新转速或新负载被误判异常 | 按机型、测点和 RPM 建参考，并补充正常工况覆盖 |
| 不同测点分布差异 | 模型学习安装位置差异 | 每个测点独立建立或选择正常参考，分组评估 |
| 机理布尔结果被当作真实标签 | 模型复制规则错误 | 只使用连续证据，布尔结果仅作工程对比 |
| 同一故障事件跨集合 | 案例评估虚高 | 按 `fault_event_id` 和 `sample_group_id` 整体管理 |
| 异常范围数量过少 | 无法证明泛化能力 | 当前只做可行性验证，持续补充独立故障事件 |
| 半直驱 4 个测点范围被当作 4 个独立事件 | 夸大有效样本量和结论稳定性 | 共享故障过程的范围统一使用同一 `fault_event_id`，按事件和测点两个层级报告 |
| 双馈跨项目测试只有异常范围 | 无法评估独立正常样本上的误报能力 | 明确定位为异常侧外部测试；半直驱使用已有维修后正常范围初步评估跨机组误报 |
| 半直驱测试只提供 1 个测点 | 测试结果不能代表全部 4 个测点 | 只对已提供且能匹配开发侧参考的测点作结论，并在后续补齐其余测点测试范围 |
| 高分由脏信号产生 | 专家候选失真 | 前置拒绝严重失真，并在内部日志中保留拒绝原因 |
| 将归一化分数解释为真实故障概率 | 业务误解 | 文档和接口明确其为正常参考异常程度 |

## 16. 实施前需要形成的数据清单

1. 双馈和半直驱的机型、机组及实际测点清单；半直驱使用 `12点/3点/6点/9点`；
2. 从文件名和波形第一列自动生成每个测点的波形长度、采样率和 RPM 统计；
3. 从文件名解析单波形采集时间、平均 RPM、采样率和测点，并保留原始路径；
4. 开发侧每个测点上线后一个自然月正常范围和完整异常验证范围，以及测试侧已提供的正常/完整异常范围；
5. 范围标签来源、故障事件编号和维修或更换时间；
6. 自动统计正常范围内各测点、RPM 区间和时间块的波形数量及相邻采样间隔，并输出使用固定 `split_seed` 形成的约 70%/30% 时间块随机切分清单及 RPM 覆盖检查；
7. 异常范围数量、独立故障事件数量，以及同一事件下各测点范围的对应关系；
8. 现有机理批处理连续输出及其逐波形追溯字段。

## 17. 分阶段实施方案

### 17.1 第一阶段：非深度基线

- 建立单波形和范围清单；
- 完成内部准入检查；
- 使用正常范围拟合现有机理连续证据的中位数/MAD；
- 输出逐波形异常排序；
- 在开发异常验证范围上由专家检查高分波形，不查看跨项目异常测试结果。

### 17.2 第二阶段：深度正常表征

- 使用正常波形训练轻量时域和频谱编码器；
- 拟合正常中心和收缩协方差；
- 生成 `deep_anomaly_score`；
- 与非深度基线使用相同范围进行对比。

### 17.3 第三阶段：分数融合

- 对深度和机理两个分支执行正常参考百分位转换；
- 固定权重融合；
- 验证机理分支缺失时退化为仅深度分数的行为；
- 只有开发异常验证范围和正常验证范围均显示稳定收益时才保留融合；方案冻结后再运行跨项目异常测试。

### 17.4 第四阶段：数据闭环

- 按 `abnormal_probability` 对异常范围和现场新数据排序；
- 专家优先复核高分和边界波形；
- 保存后续获得的逐波形人工结论，但不回填或覆盖原始范围标签；
- 独立故障事件和可靠标签积累后，再另行评估是否增加监督分类方案。

## 18. 相对原方案的主要变更

1. 训练范式由正常/故障监督分类改为仅使用确认正常范围的异常检测。
2. 输入和输出均保持单条波形，不采用多波形包作为模型输入。
3. 异常时间范围不向内部波形传播标签；开发项目完整异常范围用于验证和专家排序，外部完整异常范围只用于模型冻结后的测试，半直驱已有维修后正常范围同时纳入跨机组测试。
4. 删除监督 BCE、Focal Loss、类别均衡和缺失标签掩码。
5. 删除故障部位标签、分类头、辅助头、概率输出和相关评估内容。
6. 删除需要异常标签训练的可靠度门控，改为分支分数正常化后的固定权重融合。
7. 现有机理算法仅提供逐波形总体连续证据，不使用其布尔结论作为标签。
8. 对外输出精简为 `sample_id` 和 `abnormal_probability`。
9. 不记录 `signal_quality_level`；信号质量仅作为内部准入检查。
10. 现阶段不计算可信的逐波形分类指标，改为正常/异常范围分数分布、Top-N 专家复核和案例一致性评估；半直驱外部正常范围只支持范围来源层面的误报分析，双馈异常侧测试不报告需要正常测试样本的指标。
11. 模型只融合深度异常分数与当前波形机理异常分数，不接入外部总体统计字段。

## 19. 结论

当前数据只有少量测点级异常时间范围，没有逐波形故障标签，不适合据此训练监督式深度分类器。第一版使用开发项目上线后一个自然月的确认正常范围学习单测点、单波形正常分布：正常范围先形成不重叠时间块，再以固定随机种子按约 70%/30% 随机划分训练集和正常验证集；开发项目完整异常范围用作异常验证集，另一个项目或机组的范围用作模型冻结后的外部测试。

模型保留轻量时域编码、普通谱/包络谱双通道编码、平均 RPM 工况输入以及现有机理连续证据，但不生成任何故障部位结论。异常范围用于验证高分波形是否更集中并供专家复核，不参与正常模型拟合。`abnormal_probability` 是 `[0,1]` 的正常参考异常程度，后续业务系统可以按该分数排序，但模型本身不执行阈值决策或告警。半直驱外部测试已同时具有正常和异常范围，可初步评价跨机组误报和范围来源可分性；双馈仍只有异常范围，不能替代包含正常样本的完整跨项目测试。
